# 数据来源清单

竞赛通知要求「确保数据来源可核验」。本文件逐项说明每个输入文件
**是什么、从哪来、什么口径、什么时候取的**。

运行时读入的三个文件都会被算 sha256 并记进运行清单
（`runs/<运行编号>/10_run_manifest.json` 的 `inputs` 字段），
所以「这次跑的是哪一份数据」是可核验的。

---

## 当前状态：过渡方案

**这三个文件目前都是手工填写的示例数据，不是从年报抽取来的。**
这是刻意的过渡方案：抽取层（`algorithm/finai/extract.py`）已经能从年报 PDF
取数并带出处，但还没接进流水线。`assumptions.toml` 的文件头与
`peers.csv` 的注释里都写明了这一点。

交作品前必须替换为真实数据，步骤见 [docs/reproduce.md](../docs/reproduce.md)。

## 1. `assumptions.toml` — 经营假设与基期数据

| 小节 | 性质 | 正确来源 |
| --- | --- | --- |
| `[company]` | 元数据 | 公司公告 |
| `[drivers]` | **经营假设**（我们的判断） | 人填，每条依据登记在 `[evidence]` |
| `[wacc]` | **估值参数**（需要判断） | 国债收益率、beta 回归、行业研究 |
| `[terminal]` | **终值假设** | 长期 GDP 增速、退出倍数参考可比公司 |
| `[sensitivity]` | **分析参数**（浮动幅度） | 人填，理由写在注释里 |
| `[evidence]` | **假设依据台账** | 人填，逐条对应上面的参数 |
| `[opening_balance]` | **历史事实** —— 不是假设 | **年报资产负债表**，将来由抽取层生成 |

字段名与 `algorithm/finai/forecast.py` 的数据类一致，
每个字段的注释里写了来源状态（`✅ 已确认` / `⚠️ 待查` / `⚠️ 待替换`）。

## 2. `market.csv` — 市场快照

| 内容 | 口径 |
| --- | --- |
| 股价、总股本、有息负债、现金、少数股东权益 | **估值基准日**的市场与负债表状态 |
| 基准日 | 每行必须写 `as_of` 列，否则将来没人说得清用的是哪天的价格 |

**为什么不放利润类指标**：净利润、净资产、收入、EBITDA 属于「历史事实」，
来自年报；目标公司的利润指标则取自三表预测（前瞻口径）。三者基准日不同、
更新频率不同，混在一个文件里会让人误以为是同一时点的数据。

来源：Wind / Choice / 同花顺等终端导出。**导出数据受终端许可约束，
不要把导出文件推到公开仓库。**

## 3. `peers.csv` — 可比公司财务数据

| 内容 | 口径 |
| --- | --- |
| 营业收入、归母净利润、归母净资产、EBIT、EBITDA | **最近一个完整年度** |

代码必须与 `market.csv` 里 `role=peer` 的行一一对应；对不上的公司，
其倍数会被跳过并在运行摘要里提示。

来源：可比公司年报。同样属于「历史事实」，将来由抽取层生成。

## 运行时是否联网

- **计算链路完全不联网**：所有输入是本地文件，所有输出写本地目录。
- **唯一的网络访问是大模型接口**（DeepSeek），用于撰写报告正文。
- 不配 API key 时连这一次访问也不会发生，报告照常产出（数据版本）。

这条符合通知「在封闭或半封闭数据环境中运行」的要求：
把 `[report].enabled` 设为 `false`，整条流水线就是完全离线的。
